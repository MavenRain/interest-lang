## Core API (`src/asm.h`, `src/evm.h`, `src/evm.c`)

1. Opcodes in `Op` (`src/asm.h`): DIV 0x04, MOD 0x06, ISZERO 0x15, AND
   0x16, CALLER 0x33, GAS 0x5a, DUP3 0x82, DUP4 0x83, SWAP3 0x92, CALL
   0xf1.
2. The core label `LABEL_DATA` (`src/asm.h`): the code data of the domain.
   The core binds it after the entries and the verdict table, so no data
   byte precedes code (a PUSH byte in data cannot hide a JUMPDEST).
3. The program data type `LangDomainData` (`src/evm.h`): the start
   charter, the charter count, the genesis rows (`LangHolder`, at most
   `LANG_GENESIS_MAX` = 32), the R caps (`LangCap`), the W gates and the
   issuer pairs. `LangContract` and `EntryContext` get
   `const LangDomainData *data` (NULL gives the defaults).
4. Two domain hooks that the core calls (`src/asm.h`, `src/evm.c`):
   `lang_domain_genesis(Asm *, const LangContract *)` in the creation code
   before the runtime copy, and `lang_domain_data(Asm *, const
   EntryContext *)` at `LABEL_DATA` in both regimes.

## Checker and driver (`src/check.c`, `src/check.h`, `src/main.c`)

5. The Nat built-ins `natMul`, `natDiv` and `natMod` (`TYPE_NAT` on a
   `natMul` overflow; division and remainder by 0 give 0).
6. `lang_data` (`src/check.h`): reads the program defs `start`, `genesis`,
   `restrict`, `waterfall` and `issuers` by name and exact type, with the
   errors `CONTRACT_TYPE`, `CONTRACT_VALUE` and `CONTRACT_GENESIS`, and the
   profile code 2 (juris - 1) + (status - 1). Genesis validation also
   rejects repeated wallets before creation can overwrite their registry rows.
7. The verb `data PROG` (`src/main.c`).

Items 6 and 7 read the names of the interest-lang prelude. A kit form
needs a domain hook for the program data, and not these names in the core.

The driver buffers generated bytecode before opening the output, so a
compiler refusal preserves existing artifacts. It rejects output paths
that alias the source file, including hard links and symlinks
(`test/build-output.sh`). These protections belong in the host kit.

## Unused core entry

8. `lang_entry_amend` (`src/evm.c`) is in the core API, but no
   interest-lang entry list uses it. The interest-lang `amend` is a domain
   entry in `domain/entries.c` that writes CHARTER. The kit can keep
   `lang_entry_amend` for a domain whose `amend` writes nothing, or move it
   to the sample domain.

lang-template `fa1131a` and this tree still differ in two points. Slice K3
records them and does not change the code. A later interest-lang slice can
remove them.

- Program data. This tree keeps `lang_data` (`src/check.h`,
  `src/check.c`), the complete `LangDomainData` (`src/evm.h`) and the
  printer `verb_data` (`src/main.c`), which writes the start, genesis,
  restrict, waterfall and issuers lines. The kit core calls the domain
  hooks `lang_domain_read` and `lang_domain_print` for this work. A later

  `IO_WRITE` with exit 2, and its `test/build-output.sh` checks this. The
  driver of this tree (`src/main.c`) calls `fflush(stdout)` and does not
  examine the result.
